# Pre-registration: E22, E19 certification replayed against one fixed LLM oracle (2026-10-28)

This document fixes the design before any run. The code goes in `exp/e22_fixed_oracle_replay.py`, and the result goes to `results/icde27/e22_fixed_oracle.json`. The plan is `literature/improvement_plan_2026-10-28.md` (item E22).

## Why
E19 ran the LLM live in each arm. The live answers differed from the resolve run on 13/3333, 10/3392 and 10/2385 names (seeds 0–2). So E19 does not compare the two arms against one fixed oracle, and the paper reads it as a timing study only (PAPER_AUDIT I18/I19). The resolve run saved an answer for every labeler name (6,653). Every name the certify runs queried is among them; this was checked on 10-28 before writing this document. Those answers therefore define one complete, fixed oracle.

## Question
If every certify run uses the resolve run's answers as the oracle, is any certification false relative to the exact decisions under that same oracle? How many true dependencies are missed, and how many oracle calls does each run make?

## Fixed design
- **Workload:** the same as E19. These are the seven natural NDC candidates (`ndc(seed=0, near_miss=())`), with δ = 0.05, α = 0.05 split over the seven candidates, θ = 0.9 and ν̄ = 0.01, neighbour-only (heuristic mode).
- **Oracle:** `label(answers[v])` from `results/icde27/e19_resolve.json`. The label function is the same as E19's. No LLM is called.
- **Reference decisions:** the exact decisions of the resolve arm (`certified` in `e19_resolve.json`, g3 under the same labels < δ).
- **Certify:** Algorithm 1 exactly as in the E19 certify arm. The random streams are `e8o|seed|X|Y`, the answer cache is shared across the seven candidates of one run, and the proxy is the same hybrid index.
  - **Seeds:** 0–9. Seeds 0–2 match E19; seeds 3–9 are new and were fixed before the run.
- **Recorded per seed:**
  - each decision, U and the number of samples;
  - the number of distinct oracle calls;
  - an **estimate** of LLM time, computed as calls × the resolve arm's mean per-call latency (0.66 s). It is labelled as an estimate, never as a measured time.
- **Also recorded for seeds 0–2:** whether each decision equals the E19 live decision.

## Pre-stated expectations and criteria
- **Primary:** across the 10 seeds × 7 candidates, no certified candidate whose reference decision is "not true". Each false certification is reported. The family-wise level is α per run, so 10 runs could contain a false certification at a rate up to about 0.05 each.
- **Secondary:**
  - the number of reference-true candidates (2 of 7) missed, and in which seeds;
  - the call ratio against resolve (6,653 calls).
- **Expectation:** seeds 0–2 decide as in E19, except possibly where a changed label touches a sampled name. Seed 0's near-threshold miss of labcode→labeler (U = 0.040 live) may persist.
- **Whatever the outcome**, the result is reported. In the paper it is called a replay of saved answers, not a live run (MODIFY P1 item 5). It may replace the E19 clause "labels differ on 10–13 names per seed, so this is a timing study only". It does not change the measured E19 times.

## Not changed by this experiment
System defaults, E19's measured numbers, and Tables II, III, VI and VIII.
