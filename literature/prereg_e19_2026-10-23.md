# Pre-registration: E19, end-to-end wall clock with a live LLM oracle (2026-10-23)

This document fixes the design before any run. The code is in `exp/e19_end_to_end.py`, and the results go to `results/icde27/e19_*.json`. MODIFY.md P1 asks for a small but fair end-to-end comparison under a real oracle.

## Question
SemFD's certificate and canonicalize-all get the same oracle, the same hardware and the same concurrency. Does the certificate decide the NDC labeler dependencies in less end-to-end time?

## Fixed design
- **Workload:** the seven natural NDC candidates of E8 (`ndc(seed=0, near_miss=())`), with δ = 0.05, α = 0.05 split over the seven candidates, and θ = 0.9.
- **Oracle:** Qwen2.5-7B-Instruct Q4_K_M with the E8 system prompt and few-shot examples, temperature 0, at most 24 output tokens. It runs in one process with 16 threads (as in `e8_latency.json`), on the shared CPU server under `nice`.
  - The oracle has no inverse access, so the certificate runs neighbour-only with a declared ν̄ = 0.01. This is the **heuristic mode**, and the paper must say so next to the result.
- **Certify arm:** load the data, build the hybrid proxy index, then run Algorithm 1 for each candidate. Each LLM call is made live the first time a name is queried; the cache starts empty and is shared across the seven candidates of one run. The random streams are those of the E8 replay (`e8o|seed|X|Y`).
  - **Seeds:** 0, 1 and 2, each a separate run with its own empty cache.
- **Resolve arm:** load the data, canonicalize every labeler name live (6,653 calls, sequentially in one process), compute the exact g3 of each candidate on the LLM-resolved instance, and decide g3 < δ.
- **Order:** certify seed 0, then resolve, then certify seeds 1 and 2, so that load drift does not favour one arm.
- **Recorded per arm:**
  - wall clock from data loading to the last decision (primary);
  - model loading time (reported separately; both arms pay it once);
  - proxy-build, LLM and decision phases;
  - LLM calls and per-call latencies;
  - the 1-minute load average every 100 calls;
  - the decisions and all LLM answers.

## Pre-stated expectations and criteria
- **Consistency check:** the LLM answers should equal the cached E8 answers (the E8 replay check found 200/200 identical). The certify runs should then reproduce the E8 replay's calls (3,333 for seed 0) and decisions. Any deviation is reported.
- **Primary criterion:** the mean certify wall clock over the three seeds is below the resolve wall clock, with no false certification relative to the resolve arm's exact decisions.
- **Secondary:** true dependencies that the certificate fails to certify are counted as power losses and reported. Two quantities are reported to separate load from method:
  - the ratio of summed call latencies;
  - the ratio of calls.
- **Whatever the outcome**, the result is reported, and the claim is limited to sequential single-stream execution on this hardware. Canonicalize-all parallelizes trivially, and neither arm was run with parallel requests.
