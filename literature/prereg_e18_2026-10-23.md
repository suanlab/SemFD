# E18 사전 등록 (2026-10-23, 실행 전 작성)

IDEA_ICDE.md(아이디어 1–3, 실험 X1·X2·X5, P0-4 일부)에 대응하는 실험이다. 결과와 관계없이 보고한다. 실행 전에 기준을 고정하며, 아래 내용은 실행 뒤에 바꾸지 않는다.

## 공통 조건
- 데이터셋: geonames_16k(`{"n_cities":16000}`), tax, ndc, gpg. seed는 0–2이다.
- 후보: E1b와 같은 전체 unary 후보이다(`ds.exclude` 적용, GPG의 name↔cn 제외).
- 매 후보 난수: E1b와 같은 키 `e1b|{seed}|{x}|{y}`를 쓴다. 따라서 모든 변형이 E1b의 plain 실행과 짝을 이룬다.
- δ=0.05, α=0.05, 후보당 α/|C|, θ=0.9, k=5이다. 완전 역조회(oracle 기반)를 쓰고 공유 캐시는 변형마다 새로 만든다.
- **정합성 점검:** plain 변형은 `e1b_*.json`의 `ours_calls_total`과 인증 집합을 정확히 재현해야 한다. 재현하지 못하면 결과를 쓰지 않는다.

## 변형
1. **plain:** hybrid 프록시, 감사 후보 = 프록시 이웃 ∪ 별칭 클래스. 현재 시스템 그대로이다.
2. **refine:** 현재 구현이다. 이 후보의 앞 batch에서 가져온 별칭 클래스만 witness 개선에 쓴다.
3. **refine-warm:** 이전 후보들이 공유 캐시에 가져온 별칭 클래스도 첫 batch부터 쓴다. witness는 표본 이전 정보로만 정해지므로 TR prop:pred의 조건을 만족한다.
4. **tfidf+union:** TF-IDF 프록시, 감사 후보는 plain과 같다.
5. **hybrid+alias-only:** 감사 후보로 별칭 클래스만 쓴다(`ann=False`). 완전 역조회에서 Cor A2에 의해 ν=0이다.
6. **tfidf+alias-only.**
7. **budget-γ, γ ∈ {0.25, 0.5, 1}:** plain에 실행 전체의 지출 한도를 둔다.
   - C_full은 canonicalize-all의 정방향 호출 수이다. 정방향과 역조회 호출을 합산해, 다음 batch 전에 γ·C_full에 닿으면 인증을 멈춘다.
   - 그때 모든 tolerant 속성의 남은 값을 해소하고, 현재 후보와 남은 후보를 정확한 g3로 결정한다.
   - 이미 가져온 별칭 목록에 있는 철자는 엔터티를 이미 알므로 호출하지 않는다.
   - 이미 인증된 후보는 그대로 둔다. 후보별 α는 미리 고정했으므로 union bound는 유지된다.
   - 비용 상한: 총 호출 ≤ γ·C_full + 한 batch의 초과분 + C_full. 이 상한은 forward-only 해소 대비이며, inverse-aware 최적 대비가 아니다.
   - 사전 지정 주 설정은 **γ=0.5**(상한 1.5×C_full + 한 batch)이고, 0.25와 1은 민감도로만 보고한다.

## 측정
후보 판정(거짓 인증, 놓친 참 FD와 그 목록), 총 호출(정방향/역조회), canonicalize-all, 변형별 결정 루프 경과시간, 프록시 구축시간, 프로세스 peak RSS(데이터셋별 1개 프로세스 기준), budget 변형의 fallback 발동 여부와 시점.

## 판정 기준 (사전 고정)
- **refine / refine-warm:**
  - 거짓 인증 0을 유지하면서 놓친 참 FD를 줄이면 "검정력 개선"으로 보고한다.
  - 호출이 plain보다 5% 넘게 늘면 비용 증가로 함께 보고한다.
  - 시스템 기본값은 바꾸지 않는다(본문 표는 plain 기준).
- **2×2:** 네 데이터셋 모두에서 같은 결정을 더 적은 호출로 내는 구성이 있으면 "더 단순한 구성이 충분하다"고 보고한다. 일부 데이터셋에서만 이기면 모드별 결과로만 보고하고, 사후에 고른 최선을 시스템 성능처럼 쓰지 않는다.
- **budget-0.5:**
  - 모든 실행에서 비용 상한을 지키는지 확인한다.
  - GeoNames의 plain 대비 비용 증가가 5% 이내이고 GPG·NDC의 비용이 plain보다 낮으면 "작은 도메인 손실을 제한하면서 큰 도메인 이득을 유지한다"고 보고한다.
  - 그렇지 않으면 실패로 보고한다.
- 거짓 인증이 하나라도 나오면 그대로 보고한다. 완전 역조회에서는 정리상 실행당 확률이 α 이하이다.
